# KAD — Архитектура

## Назначение

KAD — VPN-сервис с Telegram-ботом, Mini App и собственной backend-логикой.

## Текущая известная схема

Пользователь → Telegram / Mini App → KAD Backend API → 3x-ui → VPN Node

Backend также взаимодействует с базой данных.

Статус схемы: `KNOWN`

Фактическое состояние компонентов будет проверено во время read-only аудита VPS.

## Основные архитектурные принципы

### Пользователь и Telegram

Пользователь KAD не должен быть технически равен Telegram ID.

Telegram является основным интерфейсом и способом взаимодействия, но архитектура должна позволять в будущем добавить резервный способ доступа.

Статус: `DECIDED`

### Устройства

Каждое устройство пользователя является отдельным объектом.

Это позволяет отдельно:
- отключать устройство;
- хранить его название;
- учитывать статистику;
- применять лимиты;
- заменять одно устройство без затрагивания остальных.

Статус: `DECIDED`

### Mini App

Mini App не должна напрямую управлять 3x-ui.

Правильная цепочка:

Mini App → KAD Backend → 3x-ui

Статус: `DECIDED`

### Масштабирование

Ожидаемая текущая нагрузка — около 30 пользователей.

Это целевая нагрузка, а не жёсткий технический потолок системы.

Архитектурные решения не должны создавать искусственный предел, если разумный запас роста можно сохранить без значительного усложнения.

Статус: `DECIDED`

## VPN

Текущий известный рабочий протокол: Hysteria2.

Статус: `KNOWN`

Фактическое состояние VPN требует проверки.

## Серверы

Сейчас известен один основной VPN-узел.

В будущем архитектура должна позволять добавлять дополнительные VPN-ноды без переписывания всей системы.

Статус: `PLANNED`

## Важно

Этот документ описывает архитектуру и принципы.

Пароли, токены, приватные ключи и другие секреты здесь не хранятся.
