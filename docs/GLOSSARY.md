# KAD — Глоссарий

> Краткий словарь терминов, используемых при разработке и эксплуатации KAD.

Глоссарий дополняется по мере появления новых технологий и рабочих процессов.

---

## Git и GitHub

### Repository / Repo

Репозиторий.

Каталог проекта вместе с историей его изменений, которую отслеживает Git.

---

### Working tree

Рабочая копия проекта на компьютере.

Здесь мы непосредственно создаём и редактируем файлы до commit.

---

### Tracked file

Файл, который Git уже отслеживает.

---

### Untracked file

Новый файл, который существует в папке проекта, но ещё не добавлен под контроль Git.

В `git status --short` обозначается:

`??`

---

### Staging area

Область подготовки следующего commit.

Позволяет выбрать конкретные изменения, которые попадут в историю Git.

---

### git add

Добавляет текущее состояние выбранного файла в staging area.

Не создаёт commit и ничего не отправляет в GitHub.

---

### Commit

Зафиксированный снимок изменений в истории Git.

Commit имеет собственный уникальный идентификатор и сообщение, объясняющее изменение.

---

### Commit hash / SHA

Уникальный идентификатор commit.

Например:

`d63de20`

---

### HEAD

Указатель Git на текущий commit локальной рабочей копии.

---

### Branch

Отдельная линия разработки.

Позволяет работать над изменениями независимо от основной версии проекта.

---

### main

Основная ветка репозитория KAD.

---

### origin

Локальное имя удалённого GitHub-репозитория.

Для KAD `origin` указывает на основной репозиторий проекта в GitHub.

---

### git push

Отправляет локальные commits в GitHub.

До `push` commit существует только локально.

---

### git pull

Получает новые изменения из GitHub в локальную копию репозитория.

---

### git diff

Показывает различия между состояниями файлов.

Используется для проверки изменений перед commit.

---

## Управление проектом

### SSOT

Single Source of Truth.

Авторитетный источник актуальной информации о проекте.

GitHub используется как внешний SSOT KAD для документации, истории решений и исходного кода.

Секреты хранятся отдельно.

---

### Roadmap

Высокоуровневый план развития проекта.

Показывает последовательность этапов, но не является точным списком текущих задач.

---

### Backlog

Список задач, которые потенциально или точно предстоит выполнить.

---

### Sprint

Ограниченный этап работы над выбранным набором задач.

Например:

`Stabilization Sprint`

---

### Definition of Done / DoD

Условия, при которых задача считается действительно завершённой.

Для технической задачи это может включать:

- изменение выполнено;
- результат проверен;
- существующая система не сломана;
- документация обновлена;
- при необходимости создан backup или runbook.

---

### Decision

Важное принятое решение проекта.

Фиксируется в:

`docs/DECISIONS.md`

---

### ADR

Architecture Decision Record.

Формат фиксации архитектурного решения.

Обычно включает:

- что решили;
- почему;
- последствия;
- ограничения;
- обратимость;
- условия пересмотра.

---

### Runbook

Пошаговая инструкция для конкретной эксплуатационной ситуации.

Например:

- VPN перестал работать;
- сертификат не обновился;
- бот остановился;
- требуется восстановить backup.

Цель runbook — не расследовать одну и ту же проблему заново каждый раз.

## Архитектура

### Frontend

Часть системы, с которой взаимодействует пользователь.

В KAD к frontend относится Mini App.

---

### Backend

Серверная часть приложения.

В KAD backend содержит бизнес-логику и взаимодействует с базой данных и VPN-инфраструктурой.

---

### API

Application Programming Interface.

Определённый способ взаимодействия программ друг с другом.

В KAD Mini App взаимодействует с backend через API.

---

### Database / DB

База данных.

Хранит структурированное состояние KAD, например пользователей и устройства.

---

### Dependency

Зависимость одного компонента от другого компонента или внешнего сервиса.

---

### Lock-in

Ситуация, когда систему становится сложно или дорого перенести с конкретной технологии.

---

### Migration

Перенос системы, данных или компонента на другую инфраструктуру или технологию.

---

### Rollback

Возврат к предыдущему рабочему состоянию после неудачного изменения.

---

### End-to-end / E2E

Проверка полной цепочки работы системы.

Пример KAD:

Telegram → Bot → Backend → DB / 3x-ui → VPN.

---

## Инфраструктура

### VPS

Virtual Private Server.

Виртуальный сервер, на котором работают серверные компоненты KAD.

---

### VPN Node

Узел, через который проходит VPN-трафик пользователя.

В будущем KAD должен поддерживать несколько VPN-нод.

---

### SSH

Secure Shell.

Защищённый способ удалённого управления сервером через терминал.

---

### systemd

Система управления сервисами Linux.

Используется для запуска и контроля процессов KAD.

---

### Service

Долгоживущий процесс операционной системы.

Примеры:

- `kad-bot`
- `kad-backend`

---

### Port

Числовая точка сетевого доступа к конкретному сервису.

---

### Firewall

Набор правил, определяющих разрешённый и запрещённый сетевой трафик.

---

### Monitoring

Автоматическое наблюдение за состоянием системы.

Например:

- работает ли VPN;
- работает ли backend;
- доступен ли бот;
- достаточно ли места на диске;
- действителен ли TLS-сертификат.

---

### Alert

Уведомление о проблеме, обнаруженной мониторингом.

---

## TLS и безопасность

### TLS

Криптографическая защита сетевого соединения.

Используется, например, в HTTPS.

---

### Certificate

TLS-сертификат используется для подтверждения сервера и создания защищённого соединения.

Сертификаты имеют срок действия.

---

### Private key

Приватная часть криптографической пары ключей.

Никогда не должна публиковаться в GitHub.

---

### Secret

Чувствительные данные, позволяющие получить доступ к системе.

Например:

- пароль;
- API token;
- Telegram Bot Token;
- приватный SSH-ключ;
- VPN credential.

Secrets не хранятся в публичном репозитории KAD.

---

## VPN

### 3x-ui

Панель управления VPN-инфраструктурой.

В текущей известной архитектуре KAD используется для управления VPN-доступом.

---

### Xray

Сетевое ядро, используемое 3x-ui для работы VPN-протоколов.

---

### Hysteria2

VPN-протокол последней известной рабочей конфигурации KAD.

Текущее состояние должно быть подтверждено аудитом.

---

## Резервное копирование

### Backup

Резервная копия данных или конфигурации.

Наличие файла backup само по себе ещё не гарантирует возможность восстановления.

---

### Restore

Восстановление данных или системы из backup.

---

### Disaster Recovery

Процесс восстановления после серьёзного отказа.

Например:

- потеря VPS;
- повреждение базы данных;
- потеря конфигурации;
- компрометация сервера.

---

## Статусы KAD

### VERIFIED

Факт проверен непосредственно на действующей системе.

### KNOWN

Факт подтверждался ранее, но мог измениться.

### NEEDS VERIFICATION

Факт необходимо проверить.

### PLANNED

Запланировано, но ещё не реализовано.

### DECIDED

Решение принято и действует до осознанного пересмотра.
